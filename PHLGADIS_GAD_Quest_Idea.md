# PHLGADIS GAD Quest — Concept / Product Idea

## 1. Core Idea

**GAD Quest** is a lightweight interactive feature inside PHLGADIS.

It is not meant to be a serious game, competitive gaming system, or formal examination.

Its main purpose is to make PHLGADIS more interactive during GAD-related activities, campaigns, awareness periods, and institutional events.

The basic idea is simple:

> An Admin or CHED GAD Focal creates a short GAD Quest based on a law, topic, campaign, or event. Users answer a small set of multiple-choice questions or scenarios. When they complete the quest, they can earn an achievement badge that stays on their profile.

The value is not the quiz itself. The value is the **participation history, event interaction, and badge collection**.

---

## 2. What a GAD Quest Feels Like

A user opens PHLGADIS and sees an active quest such as:

**Women's Month 2027**

- 5 short questions
- related to the current event
- available only during the event period
- badge available

The user clicks **Play**, answers the questions, sees a short explanation after each answer, finishes the activity, and receives a result.

Example:

**Scenario**

A coworker repeatedly makes unwanted comments that make another employee uncomfortable.

**What is the most appropriate response?**

- Ignore it
- Document the incident and use the proper reporting channel
- Retaliate
- Publicly shame the person

After answering, the user sees a short explanation.

The whole activity should only take a few minutes.

---

## 3. What the Questions Can Be About

Quests can be connected to:

- Republic Acts
- GAD concepts
- gender sensitivity
- safe spaces
- inclusive communication
- workplace scenarios
- school or campus scenarios
- institutional policies
- Women's Month
- 18-Day Campaign
- Safe Spaces campaigns
- specific GAD seminars or events

The Admin or GAD Focal decides what the quest is about.

---

## 4. Who Creates the Quest

Only authorized users should create quests.

Recommended creators:

- PHLGADIS Admin
- CHED GAD Focal
- authorized GAD staff

They can create:

- quest title
- description
- related event
- related law or topic
- questions
- answer choices
- correct answer
- short explanation
- badge reward
- quest availability period

---

## 5. Achievements / Badges

The main reward is a permanent profile badge.

Example:

**Achievements**

- Women's Month Champion
- Safe Spaces Advocate
- Magna Carta Awareness
- 18-Day Campaign Participant

Badges should look similar to GitHub-style profile achievements: small, collectible, and visible on the user's profile.

When a user hovers on desktop or taps on mobile, they can see:

- badge name
- related event
- related quest
- date earned
- score
- organizer

Example:

**Safe Spaces Champion**

Safe Spaces Awareness Quest  
Score: 10/10  
Awarded: March 14, 2027  
Organizer: CHED Regional Office XII

This makes the profile act as a small history of the user's GAD participation.

---

## 6. Badge Levels

Instead of giving everyone the same badge, a quest may use simple achievement levels.

Example:

- **Participant** — completed the quest
- **Advocate** — scored 80% or higher
- **Champion** — achieved a perfect score

If a user earns the highest level, only show the highest badge instead of giving all three.

The goal is to keep achievements meaningful and prevent badge clutter.

---

## 7. Leaderboard

A leaderboard can exist, but it should initially be visible only to:

- Admin
- CHED GAD Focal

Regular users do not need to see a public ranking.

The leaderboard is mainly for monitoring participation.

Example:

**Women's Month Quest**

- 187 participants
- 142 completed
- 31 perfect scores
- average score: 82%

The Admin or GAD Focal can see who participated and who scored highly.

If multiple users get the same perfect score, they can simply be tied.

Speed should not automatically decide the winner.

---

## 8. Why This Is Better Than a Daily Quiz

The system should not force users to answer random GAD questions every day just to maintain a streak.

That would eventually become repetitive.

Instead, GAD Quest should become active when there is something relevant happening.

Example yearly flow:

- Women's Month
- Safe Spaces activity
- GAD seminar
- 18-Day Campaign

Each event can have its own quest and badge.

Over time, the user builds a meaningful collection of achievements.

---

## 9. Event-Based Interaction

This is where GAD Quest can become much stronger later.

For example:

**Women's Month 2027**

User opens PHLGADIS and sees:

> Women's Month Quest is now active.

They complete the short activity and earn:

> Women's Month 2027 Champion

Later another event appears:

> Safe Spaces Awareness Quest

The user now has a reason to return and participate again.

The activity changes based on the event instead of repeating the same generic questions forever.

---

## 10. Future QR Integration

QR scanning can be added later without changing the basic concept.

Future example:

1. User attends a GAD event.
2. User scans a PHLGADIS QR code.
3. A special quest is unlocked.
4. User completes the event quest.
5. User earns an event badge.

Another version:

- scan QR at registration
- scan another QR at a booth
- complete a short scenario
- finish the event quest
- earn the badge

This can eventually make PHLGADIS part of the actual event experience.

For now, QR scanning does not need to be part of the first version.

# Possible Loopholes and How to Handle Them

## 1. Users Keep Retaking Until They Get 100%

### Problem

A user can memorize the answers and retry until they get a perfect score.

### Simple solution

For official event quests:

- allow one official attempt

or:

- first attempt counts for ranking
- later attempts are only practice

Because this is not a serious examination, there is no need for extreme anti-cheating measures.

---

## 2. Users Share Answers

### Problem

Someone can screenshot the questions and send the answers to friends.

### Simple solution

Randomize:

- question order
- answer order

Later, a quest can have more questions than each user actually receives.

But do not over-engineer this. The purpose is interaction, not exam security.

---

## 3. Too Many Perfect Scores

### Problem

If many users get 10/10, there is no clear "highest scorer."

### Solution

Treat all perfect scores equally.

Do not force a single winner unless the GAD Focal specifically designs the activity that way.

A badge can be awarded to every qualifying participant.

---

## 4. Badges Become Meaningless

### Problem

If every tiny quiz gives a badge, profiles will become full of meaningless achievements.

### Solution

Reserve badges for:

- official events
- major campaigns
- important topic quests
- special institutional activities

Small practice quizzes do not always need badges.

---

## 5. Profile Becomes Cluttered

### Problem

A user may eventually have dozens of badges.

### Solution

Show only around 5–6 featured achievements on the main profile.

Then provide:

**View all achievements**

where the complete history can be seen.

---

## 6. Questions Are Wrong or Poorly Written

### Problem

Someone may create incorrect or confusing questions.

### Solution

Only authorized GAD personnel can create quests.

A quest should be reviewed before it becomes active, especially when it discusses laws, harassment, violence, discrimination, or institutional policy.

---

## 7. Serious Topics Feel Too Much Like a Game

### Problem

Topics such as harassment or violence can feel inappropriate if the interface becomes too playful.

### Solution

Keep the interaction lightweight, but keep the wording respectful.

Avoid:

- joke reactions after wrong answers
- aggressive game terminology
- "kill streaks"
- humiliating low-score messages
- excessive celebration around sensitive scenarios

Phlia can still be friendly, but not childish.

---

## 8. Public Leaderboard Can Embarrass Users

### Problem

People may not want their low scores shown publicly.

### Solution

Keep the leaderboard private to Admin and CHED GAD Focal.

Regular users see only:

- their result
- their achievements
- their participation history

---

## 9. Users Stop Halfway

### Problem

Someone closes the browser or loses internet.

### Solution

Their current progress should be resumable.

The user returns later and sees:

**Continue Quest**

instead of starting over.

---

## 10. Too Many Quests Become Annoying

### Problem

If Admin constantly creates quests, users may ignore them.

### Solution

Use GAD Quest primarily for meaningful moments:

- campaigns
- events
- awareness activities
- selected educational topics

Quality is more important than quantity.

---

# Overall Experience

The feature should feel like this:

**Event or GAD topic**

↓

**A short GAD Quest becomes available**

↓

**User answers a few questions**

↓

**User learns something through short explanations**

↓

**User completes the activity**

↓

**User earns an achievement**

↓

**Achievement stays on the profile**

↓

**Admin and GAD Focal can see participation**

Later:

**Physical event**

↓

**QR interaction**

↓

**Quest**

↓

**Achievement**

---

# Main Design Principle

> **Interaction first. Gaming second.**

The system should not feel like PHLGADIS suddenly became a video game.

The purpose of GAD Quest is to add a small layer of interaction and recognition to the existing platform.

The most important parts are:

- short quests
- event relevance
- useful questions
- achievement badges
- visible participation history
- simple private analytics for GAD staff
- future QR event integration

Everything else is optional.
